# 2026-11-02 UI 작업 현황·HUD 실행 계획

2026-11-03 Git 공유 대상: 검증한 HUD·MP·아이템 표시 코드/리소스, 이 문서와 최신 확인 화면. 사용자 요청 커밋 제목은 `HUD·MP 개선`, 게시 대상은 `origin/cy`다. 아래 ‘미커밋·미푸시’ 문구는 11월 2일 각 구현 단계 당시의 이력이다. 레퍼런스 수집·거절된 시안 폴더, 기존 이펙트 meta 6개와 사용자 PDF는 이번 공유 대상에서 제외한다.

**현재 단계: 중앙 고정 HUD·효과/쿨타임 분리·MP 즉시 초당 2 회복·직업 아이콘 즉시 갱신을 반영했다. 격리 Unity에서 9종 해상도 회귀 1,225개 검사와 메뉴/장착 갱신 추가 24개 검사가 통과했다. 실제 다른 PC의 플레이 검증은 미실시다. 아래 504개·362개 검사는 이전 우하단 디자인 당시 기록이다.** 오늘 작업의 진행·검증·변경 기록은 이 문서에서만 갱신한다. 과거 완료 현황은 [기존 계획서](../CHANYOUNG_PLAN.md)와 [통합 검토 기록](CY_MERGE_REVIEW.md)에 보존하며, 오늘의 완료 항목에 합산하지 않는다.

### 중앙 고정 HUD — 최신 승인

- 사용자가 **56×56 기준 크기·12px 간격·좌상단 단축키·스킬명 툴팁·중앙 쿨타임 숫자와 테두리·미습득 잠금·하단 중앙 배치**를 승인했다. 아이콘 그림 영역도 50×50(슬롯 폭의 약 89%)로 확대한다. HP·MP 바는 기존 기준 240×8px와 실제 자원 연동을 유지한다.
- 56px은 기준 단위다. HUD의 복제 `PanelSettings`를 통해 화면 크기에 따른 균일 배율을 적용한다. 같은 해상도에서는 같은 좌표와 크기를 계산하며, 물리 DPI를 배율의 직접 원본으로 삼지 않는다. 기존 해상도 배율 1~1.5와 화면 밖 잘림 방지 상한을 함께 사용한다. 기준 1280×720에서는 56px, 1920×1080과 4K에서는 84px 아이콘이다. 공용 PanelSettings 에셋·다른 메뉴 배율은 바꾸지 않는다.
- 안내가 나타날 때 HUD를 움직이려던 제안은 사용자의 검토를 반영해 철회했다. 사용자가 **“첫 번째 안으로 진행… HUD는 하단 중앙에 고정… F 상호작용·대화·차징 안내는 HUD 위쪽… 동시에 표시되어도 겹치지 않게”**라고 별도 승인했다. 기존 안내 위치 유지 지시의 예외는 이 세 안내에만 적용한다. HUD 위에서 아래부터 차징, F 상호작용, 대화 순서로 쌓고 툴팁은 표시 중인 안내보다 위에 둔다. 안내 문구·입력·게임 수치·메뉴·사망 안내 동작은 보존한다.
- 툴팁은 런타임 마우스 위치로 슬롯 영역을 조회해 표시한다. UI 요소는 계속 `PickingMode.Ignore`와 포커스 비활성을 유지하므로 툴팁을 위해 전투 클릭을 가로채지 않는다. 이름·미습득 안내·일석이조의 좌클릭 버프 후 우클릭 평타 사용 순서를 툴팁에서 확인할 수 있다.
- 중앙 배치 변경은 `CombatHud.cs`, `SkillCooldownIcon.cs`, `CombatHud.uxml`, `CombatHud.uss`, `PrototypeHud.cs`다. 이후 추가 승인으로 `PlayerSkills.cs`의 효과 지속 길이 읽기용 기록과 `PlayerMana.cs`의 회복 수치 0초/초당 2만 수정했다. 기존 쿨타임·효과 지속 시간·피해·장착 제한·아이템·씬 설정은 바꾸지 않았다.
- 격리 검증은 완료했다. 실제 다른 PC에서 확인했다고 보고하지 않는다. 검증용 입력 드라이버는 격리 복사본에만 있고 실제 프로젝트 런타임에는 추가하지 않는다.
- **추가 승인 — 효과/쿨타임 분리:** 중앙 숫자는 실제 쿨타임 전용이다. 직업 특수 아이콘 아래 별도 `효과` 라벨과 청록색 막대로 실제 효과 남은 시간을 표시하며, 효과가 끝나면 이 두 표시만 숨긴다. 일석이조 5초·패링 약 0.7초를 그대로 사용하고 가짜 최소 표시 시간은 추가하지 않는다. 표시 공간은 항상 확보해 활성/종료 때문에 HUD가 움직이지 않게 한다. `PlayerSkills.SpecialActiveDuration`에는 실제 `specialEndsAt - Time.time`을 읽기용으로 기록하며 스킬 지속 시간과 쿨타임 설정을 바꾸지 않는다.
- **추가 승인 — MP 회복:** 사용자가 **“즉시 초당 2로 수정”**을 승인했다. 이제 `RecoveryDelay=0`, `RecoveryPerSecond=2`가 최신 임시 정책이며, 아래 이전 기록의 ‘2초 대기 후 초당 5’보다 우선한다. 최대치 100·스킬 비용·사망 중 회복 정지·기존 MP 수명은 유지한다. 스킬창의 회복 안내도 이 값에 맞춘다.
- **직업 아이콘 버그 재현·수정:** 스킬을 쓰지 않고 궁수→전사로 바꿨을 때 Q/E/직업 특수 모두 이전 그림 픽셀이 유지되는 현상을 격리 Unity에서 재현했다(`CLASS_ICON_REPRO_OK checks=9`). `Image.uv`를 변경해도 자식 이미지가 다시 그려지지 않았으며 색상 변경이 재그리기를 일으켜 사용 후에야 그림이 바뀌었다. 그림 종류가 바뀔 때 `art.MarkDirtyRepaint()`를 호출하도록 수정했다. 9종 해상도에서 3직업을 사용 없이 전환하고 실제 픽셀을 비교했으며, 메뉴 중 직업 변경→닫기·같은 직업의 스킬 교체·해제/재장착·직업별 사용자 장착 복원도 확인했다(`CLASS_ICON_FIX_OK checks=24`). [Unity 6.0 Image 소스](https://github.com/Unity-Technologies/UnityCsReference/blob/6000.0/Modules/UIElements/Core/Controls/Image.cs)에서도 uv setter의 재그리기 누락 경로를 확인했다.
- **조건 보존:** `SkillLoadout.cs`는 변경하지 않았다. 일반 스킬 2칸·습득한 보스 전용 1칸·직업 특수 고정 구조, 타 직업·중복·범위 밖 슬롯·미습득 보스 장착 거부는 기존 코드를 원본으로 삼는다. HUD의 5개 표시는 일반 장착 5개를 뜻하지 않는다.
- **최신 검증:** Unity 6000.0.60f1에서 `CENTERED_HUD_OK checks=1225`. 9종 해상도 각각에서 고정 중앙 좌표·56 기준 아이콘/12 간격·약 89% 그림 영역·기존 240×8 HP/MP·숫자/테두리·자물쇠·3직업 즉시 렌더 갱신을 검사했다. UI Toolkit reference/fallback DPI를 96/144/192로 바꿔도 같은 해상도의 좌표/크기가 유지됐다. 이는 실제 OS DPI를 바꾸거나 다른 PC에서 플레이한 검증을 뜻하지 않는다. 차징/F/대화의 8가지 조합×9종=72개 경우에서 HUD 고정·안내/툴팁의 화면 내부 배치와 비겹침을 확인했다.
- **추가 동작 검증:** 중앙 숫자는 실제 남은 쿨타임을 올림해 표시하고 준비되면 0 표시 없이 숨긴다. 효과 종료 후 숫자가 남는 것, 패링의 0.7초 종료에 가짜 지연이 없는 것, 효과 종료로 HUD가 움직이지 않는 것을 확인했다. 즉시 초당 2 MP 회복·일시 정지·사망 중 정지·스킬 비용 및 쿨타임 유지도 확인했다. 장착 API의 타 직업/중복/세 번째 일반 슬롯/보스 전용 슬롯/미습득 보스 거부, 거부 시 장착 상태 유지, 미장착·무기 미장착의 기존 사용 거부와 무소모를 검사했다. 메뉴/인벤토리에서 HUD와 툴팁이 함께 숨는 것도 확인했다.
- **최신 파일:** `Docs/Previews/CombatHudFinal/open-preview.html`을 더블클릭한다. 같은 파일 위치를 유지하면서 중앙 HUD·직업별 사용 전 그림·효과 활성/종료 비교·동시 안내 영역 화면으로 갱신했다. `hud-*.png`, `class-*.png`, `cooldown-*.png`, `archer-buff-tooltip.png`, `effect-ended-cooldown-continues.png`, `guides-all-*.png`가 최신 캡처다. `guides-all-*`의 영문 상자는 실제 OnGUI 문구 캡처가 아니라 같은 `GetGuideRects` 결과에 그린 검증용 영역이다. 실제 HUD/툴팁은 Unity 렌더다. 1280×480 동시 안내와 효과 활성/종료·1920×1080 직업 그림을 직접 열어 확인했다.
- **근거/한계:** 상세 검사·렌더는 `Library/Validation/CenteredHudResults/`, `ClassIconReproResults/`, `ClassIconFixProbeResults/`에 보관했다. C#은 `Library/Validation/CenteredHudProbe.cs`, `ClassIconRepro.cs`, `ClassIconFixProbe.cs`, `CenteredTooltipDriver.cs`에 격리했다. 실제 원본 Town/Field 전환 플레이·다른 PC/OS 배율·Windows Player 빌드 검증은 하지 않았다. 이번에 확인한 조건을 통과했다는 뜻이며 게임 전체에 다른 버그가 없다는 보증으로 보고하지 않는다. 직접 구현·검증했고 위임·커밋·푸시는 하지 않았다.

### 이전 추가 승인·결과 (우하단 HUD 당시)

이 절이 아래 초기 계획·이력보다 우선한다. 구현 변경은 미커밋·미푸시이며 복구 기준 커밋은 `cbfb084`다.

- **추가 승인:** 사용자가 강한 스킬일수록 MP가 많이 소모되어야 한다고 요청했고, 비용·회복·실패 처리 확인에 **“이대로 소모·회복 연결”**로 답했다. 아래 수치는 이번에 새로 승인한 임시값이며 PDF의 원래 기획값이 아니다. 기존 쿨타임·피해·공격 효과는 그대로다.

| 대상 | MP |
|---|---:|
| 회피 | 5 |
| 오지마 / 원형베기 | 15 |
| 화살 비 / 힐링 존 | 25 |
| 저격 / 엑스칼리버 / 심판 | 30 |
| 디버프 해제 | 20 |
| 연속베기 | 타격 입력당 6 (1/2/3타 = 6/12/18) |
| 일석이조 / 패링 / 부활 | 30 / 10 / 40 |
| 보스 스킬 | 50 |
| 평타 (일석이조 중 2연사 포함) | 0 |

- **자원·수명:** 최대 100. 마지막 성공 소모 2초 후 초당 5 회복. 사망 중 회복 정지. 새 전역 수명 구조 대신 기존 `ItemSession`에 세션용 `PlayerManaState`를 보관한다. 메뉴·장착·직업 변경·플레이어 재생성으로 초기화하지 않는다. 사망 후 Town의 기존 씬 콜백에서 최대치를 복구하며 일반 씬 이동은 값을 유지한다. 부활 후에는 현재 MP에서 회복을 재개한다. 디스크 저장 스키마는 바꾸지 않는다. 실제 자원 `PlayerMana`가 기존 `IManaSource`를 구현해 HUD가 읽는다.
- **소비 시점:** 즉시·준비 동작은 성공한 사용 시작, 화살 비·저격·엑스칼리버는 발사 시점, 심판은 채널 시작 시 한 번, 연속베기는 각 입력, 부활은 성공 시점이다. MP 부족은 사용·소모·쿨타임 시작을 막는다. 미발동 조준·차징 취소는 무료다. 이미 시작한 원형베기의 준비 동작·심판 채널을 중단하는 것은 조준 취소와 구별하고 기존 쿨타임 정책을 보존한다. 포션·장비 MP 능력치·새 저장 시스템은 제외한다.
- **입력·HUD:** 우하단 240px 폭, 24px 아이콘 다섯 개를 같은 기준선에 배치했다. 작은 스킬명·키를 붙이고 `준비`·남은 초 문구를 없앴다. 실제 쿨타임으로 테두리가 채워지며 MP 부족은 사용 불가 색으로 표시한다. 일석이조는 왼쪽 버튼 강조 마우스 → 오른쪽 버튼 강조 마우스로 사용 순서를 보이고, 버프 중 오른쪽 버튼을 강조한다. 다른 직업 특수는 왼쪽 마우스 하나만 표시한다. 일석이조의 우클릭 화살 표시 자체는 사용자가 직접 확인했다. 기존 스킬창에 사용 안내·MP 비용·임시 회복 규칙을 보완했다. 평타 발사 로직은 변경하지 않았다.
- **해상도·바 확대 최종 승인:** 사용자는 위치·기존 색/디자인을 유지하면서 바 자체 폭 240px, HP·MP 높이 모두 8px, 라벨·수치 가독성 개선을 승인했다. 실제 바를 각각 240×8px로 맞추고 11px 라벨/수치를 바 윗줄 양끝에 두었으며 스킬과 10px 간격을 확보했다. 아이콘 크기·기준선·다른 안내 좌표는 유지했다. HUD 자체에만 1~1.5 배율을 적용해 저해상도에서도 아이콘 24px 하한을 둔다. 공용 PanelSettings 에셋과 다른 메뉴 배율은 바꾸지 않는다.
- **아이콘 출처:** 전용 스킬 아이콘은 원래 없었다. 최초 임의 추가한 단순 픽셀 기호를 제거했고 `Resources/UI/SkillIconAtlas.png`를 ImageGen으로 새로 제작했다. 1254×1254의 4×4 아틀라스를 원본 변형·meta 슬라이싱 없이 `Image.uv`로 표시한다. 모드 `generate`, 불투명 배경. 제작 프롬프트 요약: `4x4 fantasy pixel-art skill icon atlas, consistent dark charcoal-blue backgrounds and restrained bronze frames, readable silhouettes at small size; empty, dodge boot, knockback bow, arrow rain; snipe, whirlwind, combo slash, greatsword; healing circle, cleanse crystal, holy beam, boss comet; double arrows, parry shield, revive cross, lock.` 신규 제작이며 원래 게임 아이콘으로 보고하지 않는다.
- **검증:** Unity 6000.0.60f1 격리 복사본에서 `MANA_HUD_OK checks=504`. 위 비용, 부족 시 차단, 조준 취소, 최대 차징 자동 발사 한 번 과금, 1/2/3타, 대상 없는 부활, 실제 부활 HP/쿨타임, 평타 무료, 회복 지연·재시작·속도·상한, 일시 정지, 사망 중 회복 정지, 메뉴/인벤토리 숨김, 직업·장착 변경과 플레이어 재생성의 MP 유지, 마우스 강조를 확인했다. 800×600, 1024×768, 1280×480, 1280×720, 1366×768, 1920×1080, 2560×1080, 2560×1440, 3840×2160의 정렬·화면 내부 배치·실제 빨강/파랑 픽셀을 검사하고 렌더 캡처를 저장했다. 복사본 초기 실행의 라이선스 접근 문제는 검증용 프로세스만 종료·재실행해 해소했다.

### 현재 코드에서 확인한 내용

1. `World/PrototypeHud.cs`는 IMGUI로 상단 HP와 Q/E/Shift/Space/특수 쿨타임을 텍스트로 표시한다. 하단 HP바·MP바는 없다.
2. HP는 `Combat/Health.cs`의 `Current/Maximum/Changed`를 사용할 수 있다.
3. `PlayerSkills.Cooldown(SkillId)`, `SpecialRemaining`, `ArcherController.BackstepRemaining`에 실제 남은 시간이 있다. HUD에 별도의 가짜 타이머를 만들지 않는다.
4. Q/E는 장착된 일반 스킬 두 개이며, Shift는 습득·장착 조건이 있는 보스 스킬이다. 좌클릭은 직업 고정 특수, Space는 회피다. 장착을 바꾸면 HUD도 실제 스킬 이름·상태로 바뀌어야 한다.
5. MP 자원·소모·회복은 현재 미구현이다. `CLASS_SKILLS.md`에도 MP 미연결로 기록돼 있다. MP 포션 이미지만 존재하며 사용 효과는 미확정이다.
6. 아이템 PNG는 모두 512×512이며 투명 여백의 비중이 다르다. 예: 모자 가시 영역 352×336, 재료 1은 272×352, HP 회복약은 288×400. 이미지 전체를 그대로 Fit하면 칸 대비 그림이 작아진다.
7. 현재 슬롯 이름은 이미 11이다. 추가 작업은 글자를 계속 줄이는 것에만 의존하지 않고, 투명 여백과 아이콘 표시 영역을 함께 개선한다.

### HUD 배치와 표시 규칙

**아래는 최초 초안의 기록이며 최신 배치는 이 문서 마지막의 “소형 HUD 재구현”을 따른다.** 큰 중앙 박스·상태 문구·남은 초는 사용자 검토에서 거절되어 제거 대상이다.

```text
                  HP  빨간 막대  현재 / 최대
                  MP  파란 막대  현재 / 최대
 [Space 회피] [Q skill1] [E skill2] [좌클릭 직업 특수] [Shift 보스]
```

- 하단 중앙에 작은 한 묶음으로 배치한다. HP가 위, MP가 아래이며 두 바의 길이를 맞춘다. 색만으로 구별하지 않도록 HP/MP와 현재/최대 수치도 함께 표시한다.
- 스킬 칸은 아이콘/식별 기호와 단축키가 중심이다. 긴 이름·세부 설명은 툴팁으로 옮기고 본문 전체가 긴 텍스트로 채워지지 않게 한다. 기존 사용 가능한 이미지를 우선 사용하며 없는 스킬 아이콘은 서로 구분되는 임시 기호로 표시한다.
- 쿨타임 중에는 음영과 실제 남은 초를 함께 표시한다. 1초 이상은 올림 정수, 1초 미만은 올림 소수 한 자리로 표시하고 실제 0이 되기 전에는 준비 완료로 표시하지 않는다. 진행률을 만들려고 기존 쿨타임 설정을 재구성하지 않는다.
- 상태 우선순위는 **미습득 > 미장착 > 사용 중/조준·차징 > 쿨타임 > 사용 불가 > 준비**로 통일한다. 특히 미습득 보스 스킬과 빈 슬롯을 쿨타임 0이라는 이유로 준비 상태로 표시하지 않는다. MP 부족 판정은 MP 코어와 함께 보류하며, 후속 연결 시 쿨타임보다 낮고 준비보다 높은 우선순위로 둔다.
- 직업 특수의 효과 지속 시간과 재사용 대기시간을 구별한다. 연속베기의 3회 연결과 조준/차징 후 발동 시점도 기존 로직에 맞춘다.
- HP·쿨타임은 실제 게임 상태를 읽는다. MP는 후속 상태 공급자가 연결되기 전까지 **`MP — / —`와 파란 미연결 바**로 표시하며 가짜 최대/현재 값을 만들지 않는다. 표시용 시간 누적이나 HUD의 별도 자원 사본을 원본으로 삼지 않는다.
- 전투 HUD는 클릭을 가로채지 않는다. 인벤토리·대장장이·캐릭터 메뉴와 겹치지 않게 숨김/우선순위를 정한다. 사망 안내·대화·상호작용·차징 안내의 위치도 하단 HUD와 겹치지 않게 조정한다.
- 기존 상단 HP/쿨타임 박스는 새 HUD 연결을 확인한 후 제거한다. 기존 ESC 스킬/직업 메뉴를 전부 새 UI로 바꾸는 작업은 포함하지 않는다.

### 기존 시스템 보존과 MP 코어 보류

**최종 결정: 이번에는 HUD·아이템 표시만 구현한다. MP 정책 구현과 기존 쿨타임 중앙화는 제외한다.** 현재 코드와 `개발_세부사항.pdf`를 기준으로 기존 직렬화 값·쿨타임·스킬 동작을 유지한다. PDF의 쿨타임·MP 추후 수정 문구를 임의 변경의 근거로 사용하지 않는다.

기존 `ItemSession`과 스킬 상태의 씬 간 유지 구조를 확인했다. HUD는 기존 상태를 조회하고, 회피 등 기존 수명 차이를 이번에 수정하지 않는다. MP 후속 작업도 기존 구조를 먼저 확인하며 새로운 전역 상태나 `DontDestroyOnLoad` 구조를 임의로 추가하지 않는다.

**쿨타임은 현재 구현값을 그대로 유지한다.** 실제 씬의 직렬화 값이 있으면 해당 값을 읽는다. MP 수치는 이번에 확정하지 않는다.

- 앞서 제안한 MP 비용·최대치·회복 수치는 이번 실행 계획에서 제외한다. 후속 승인 없이 적용하지 않는다.
- MP 포션·저장 스키마·장비 MP 능력치·레벨/서버 시스템도 이번 범위에 추가하지 않는다.

### 아이템이 텍스트보다 먼저 보이게 하는 작업

- 기존 확대 슬롯과 스크롤·화면비 대응을 유지한다. 아이콘을 키우려고 슬롯 자체를 다시 작게 만들지 않는다.
- 원본 PNG·아이템 ID·기존 에셋 GUID를 보존한다. 원본의 투명 여백을 조사한 결과를 이용해 **UI 표시용 영역**을 보정하고 작은 패딩만 남긴다. 원본을 잘라 저장하거나 새 원화로 교체하지 않는다.
- 공통 `UpgradeItemIcon` 경로에서 표시를 일관되게 적용한다. 장착 슬롯·가방·제작 화면에서 같은 아이템의 그림 비율이 어긋나지 않게 확인한다.
- 아이콘에는 충분한 고정 영역을 주고 슬롯 이름은 11 수준의 보조 정보로 유지한다. 수량·강화 단계 숫자가 그림을 덮지 않게 모서리로 분리한다. 긴 설명은 기존 상세 영역과 툴팁에 둔다.
- 후광 색·맥동, +1/+2/+3 구분, 아이템 원본 색, 세트 효과와 장착/해제 동작을 보존한다. 여백 보정용 Sprite를 만들면 캐시·정리를 포함해 매 프레임 생성하지 않는다.

### 적용할 스킬과 구현 경로

- **Unity UI / UI Toolkit**: 기존 인벤토리와 같은 런타임 UI 체계로 HP/MP 막대·쿨타임 칸·공통 아이콘 가독성을 구현한다. 공유 PanelSettings 에셋을 직접 바꿔 다른 창의 배율을 흔들지 않는다.
- **Unity IMGUI**: 기존 `PrototypeHud.OnGUI`의 중복 상태 표시 제거와 안내 위치 조정에만 사용한다. 기존 ESC 메뉴 전체를 교체하지 않는다.
- **Unity CLI**: 실제 Unity 컴파일·Play Mode·렌더링 검증에 사용한다. 테스트 저장과 검증 코드는 복사본/로컬 검증 경로에 격리한다. 기존 실행 중인 Editor를 종료하거나 연결 패키지를 무단 설치하지 않는다.
- 이미지 생성·새 패키지·전체 게임 폴리시는 필요한 작업으로 확인되지 않았으므로 이 계획에는 포함하지 않는다.
- 라우팅: 현재 세션에서 직접 조사·계획 작성. 위임 없음. 향후 별도 위임이 필요하면 승인 범위와 기존 미커밋 변경을 전달한다.

예상 코드 범위: `PrototypeHud`, 필요한 읽기 전용 상태 조회 API, 새 전투 HUD(UXML/USS/바인딩), MP 후속 읽기 연동 지점, 공통 아이콘 표시 보정 및 필요한 인벤토리/제작 스타일. MP 코어·밸런스 데이터는 제외한다. 기존 public 메서드·클래스 이름을 불필요하게 바꾸지 않는다. 원본 씬·기존 이펙트·다른 사람의 메타 변경은 수정 대상이 아니다. 실제 파일 목록이 범위를 벗어나면 먼저 이 문서에 이유를 적고 승인 범위를 확인한다.

### 초기 HUD 구현 결과와 검증 범위 (이전 디자인·MP 보류 당시)

- **HUD:** 하단 HP는 `Health.Current/Maximum`, Space/Q/E/좌클릭/Shift는 기존 남은 시간과 사용 상태를 읽는다. 장착 변경·미장착·보스 미습득·조준·차징·연계·사용 중을 구별한다. 상단 중복 박스만 제거했고 기존 ESC 메뉴·사망 안내·조작은 보존했다. 인벤토리/대장장이 공통 차단 조건 및 ESC 메뉴에서 전투 HUD를 숨긴다. HUD의 모든 요소는 포인터 선택·포커스를 받지 않는다.
- **MP:** 미연결 시 파란 영역과 `MP — / —`. 후속 구현은 해당 씬의 `CombatHud.BindManaSource(IManaSource)`에 실제 자원 공급자를 연결하면 된다. 인터페이스는 `Current/Maximum` 읽기만 제공한다. 게임 MP 자원·소모·회복·비용은 구현하지 않았다. 테스트의 임시 공급자는 검증 복사본에만 있다.
- **아이템:** 원본 PNG와 같은 텍스처를 사용하는 표시용 Sprite를 캐시한다. 14종의 투명 경계는 사전 계산된 `ItemIconBounds.json`에서 읽으며 런타임 픽셀 검사나 매 프레임 Sprite 생성을 하지 않는다. 장착·가방·제작의 공통 `UpgradeItemIcon`에 적용한다. 기존 슬롯 크기와 보조 글자 11, 강화 수준·후광 경로는 유지한다.

### 작업 이력

### 소형 HUD 재구현 이력 (아래 최신 승인 기록 우선)

**최신 사용자 정정이 아래 초기 재구현 항목보다 우선한다:** 우하단 배치, 새 전용 아이콘 중심·스킬명/키 보조 표시, 기존 차징·상호작용·대화 안내 좌표 복원, MP 기본 100/100 표시. 원래 전용 스킬 아이콘이 있던 것은 아니며 최초의 단순 픽셀 기호는 임의 추가였음을 사용자에게 설명했고 교체한다. 새 이미지 에셋은 이번에 제작한 것으로 기록한다. MP 기본 수치 표시는 새 UI 지시이며 자원 소모·회복 구현은 아니다.

- 승인: 단순한 실제 HUD 레퍼런스 제안에 대한 사용자 **“ㄱㄱ”**. 우하단 엇갈린 원형 시안과 대형 MMO 단축바는 사용하지 않는다.
- 현재 반영: 좌하단 180px 폭의 작은 묶음. HP·MP는 얇은 두 줄이며 그 아래 24×24 아이콘 다섯 개를 같은 기준선에 정렬했다. 키만 남기고 스킬 이름·준비·남은 초 라벨과 큰 배경 판을 제거했다. 직업과 장착 스킬에 따라 작은 픽셀 식별 기호가 바뀐다.
- 쿨타임: 기존 `SetCooldown`의 실제 `seconds` 인자와 성공한 특수 사용의 실제 남은 시간을 HUD 전용 길이 기록으로 보관한다. 기존 `Ready`가 사용 가능 여부를 판정하는 원본이며 HUD 기록은 게임 판정에 사용하지 않는다. 기존 수치를 공통 밸런스 데이터로 옮기거나 새 수치를 정의하지 않았다. 회피는 기존 직렬화 값의 읽기 전용 getter를 사용한다. 장착 변경·씬의 플레이어 재생성에서도 기존 쿨타임 길이 기록을 유지하며 세션 초기화 때 함께 정리한다.
- 보존: MP 공급 인터페이스만 유지, 미연결은 `MP —`. MP 코어·피해·사용 조건·쿨타임 수치·아이템 UI·씬·패키지는 변경하지 않는다.
- 단계: **코드 반영 완료/검증 전**. 이후 실제 Unity 렌더·정렬·테두리 충전·잠금/미장착·메뉴 비간섭을 확인하고 이 항목을 갱신한다. 위 최초 HUD 검사 203개는 이전 디자인의 기록이며 이번 수정의 통과 결과로 재사용하지 않는다.
