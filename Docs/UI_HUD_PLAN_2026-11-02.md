# 2026-11-02 UI 작업 현황·HUD 실행 계획

**현재 단계: 사용자 보완 조건과 최종 범위를 반영해 계획 확정. 새 HUD·아이콘 구현은 미착수. MP 코어는 보류.** 오늘 작업의 진행·검증·변경 기록은 이 문서에서만 갱신한다. 과거 완료 현황은 [기존 계획서](../CHANYOUNG_PLAN.md)와 [통합 검토 기록](CY_MERGE_REVIEW.md)에 보존하며, 오늘의 완료 항목에 합산하지 않는다.

### 사용자 요청과 적용 범위

- 화면 하단에 **빨간 HP바**, 바로 아래 **파란 MP바**를 표시한다. 예시 사진은 HP와 쿨타임 배치의 참고이며 다른 UI나 게임 화면까지 재현하지 않는다.
- 하단에 **회피 / 장착 skill1 / 장착 skill2 / 직업 고정 특수 / 보스 스킬**의 실제 쿨타임과 단축키를 표시한다. Space 표기는 현재 게임 기준으로 **회피**로 통일한다.
- 인벤토리·장착 슬롯 등은 아이템 그림이 먼저 보이고 글자는 보조가 되도록 만든다.
- **현재 코드와 저장소 루트의 `개발_세부사항.pdf`를 최상위 기준으로 삼는다.** 기존 동작·쿨타임·직렬화 값·씬 설정을 변경하거나 쿨타임을 중앙화하지 않는다.
- 사용자 최종 선택은 **“HUD·아이템 표시만, MP 코어 보류”**다. MP바와 후속 읽기 연동 지점만 만들며, MP 자원·소모·회복·비용·밸런스 데이터·저장 구조는 이번에 추가하지 않는다.
- 이번 계획 승인과 범위 선택은 HUD·아이템 표시 및 필요한 읽기 전용 조회에 한정한다. 기존 전투 시스템 변경으로 확대하지 않는다.

### 현재 코드에서 확인한 내용

1. `World/PrototypeHud.cs`는 IMGUI로 상단 HP와 Q/E/Shift/Space/특수 쿨타임을 텍스트로 표시한다. 하단 HP바·MP바는 없다.
2. HP는 `Combat/Health.cs`의 `Current/Maximum/Changed`를 사용할 수 있다.
3. `PlayerSkills.Cooldown(SkillId)`, `SpecialRemaining`, `ArcherController.BackstepRemaining`에 실제 남은 시간이 있다. HUD에 별도의 가짜 타이머를 만들지 않는다.
4. Q/E는 장착된 일반 스킬 두 개이며, Shift는 습득·장착 조건이 있는 보스 스킬이다. 좌클릭은 직업 고정 특수, Space는 회피다. 장착을 바꾸면 HUD도 실제 스킬 이름·상태로 바뀌어야 한다.
5. MP 자원·소모·회복은 현재 미구현이다. `CLASS_SKILLS.md`에도 MP 미연결로 기록돼 있다. MP 포션 이미지만 존재하며 사용 효과는 미확정이다.
6. 아이템 PNG는 모두 512×512이며 투명 여백의 비중이 다르다. 예: 모자 가시 영역 352×336, 재료 1은 272×352, HP 회복약은 288×400. 이미지 전체를 그대로 Fit하면 칸 대비 그림이 작아진다.
7. 현재 슬롯 이름은 이미 11이다. 추가 작업은 글자를 계속 줄이는 것에만 의존하지 않고, 투명 여백과 아이콘 표시 영역을 함께 개선한다.

### HUD 배치와 표시 규칙

```text
                  HP  빨간 막대  현재 / 최대
                  MP  파란 막대  현재 / 최대
 [Space 회피] [Q skill1] [E skill2] [좌클릭 직업 특수] [Shift 보스]
```

- 하단 중앙에 작은 한 묶음으로 배치한다. HP가 위, MP가 아래이며 두 바의 길이를 맞춘다. 색만으로 구별하지 않도록 HP/MP와 현재/최대 수치도 함께 표시한다.
- 스킬 칸은 아이콘/식별 기호와 단축키가 중심이다. 긴 이름·세부 설명은 툴팁으로 옮기고 본문 전체가 긴 텍스트로 채워지지 않게 한다. 기존 사용 가능한 이미지를 우선 사용하며 없는 스킬 아이콘은 서로 구분되는 임시 기호로 표시한다.
- 쿨타임 중에는 음영과 실제 남은 초를 함께 표시한다. 1초 이상은 올림 정수, 1초 미만은 올림 소수 한 자리로 표시하고 실제 0이 되기 전에는 준비 완료로 표시하지 않는다. 진행률을 만들려고 기존 쿨타임 설정을 재구성하지 않는다.
- 상태 우선순위는 **미습득 > 미장착 > 사용 중/조준·차징 > 쿨타임 > 사용 불가 > 준비**로 통일한다. 특히 미습득 보스 스킬과 빈 슬롯을 쿨타임 0이라는 이유로 준비 상태로 표시하지 않는다. MP 부족 판정은 MP 코어와 함께 보류하며, 후속 연결 시 쿨타임보다 낮고 준비보다 높은 우선순위로 둔다.
- 직업 특수의 효과 지속 시간과 재사용 대기시간을 구별한다. 연속베기의 3회 연결과 조준/차징 후 발동 시점도 기존 로직에 맞춘다.
- HP·쿨타임은 실제 게임 상태를 읽는다. MP는 후속 상태 공급자가 연결되기 전까지 **`MP — / —`와 파란 미연결 바**로 표시하며 가짜 최대/현재 값을 만들지 않는다. 표시용 시간 누적이나 HUD의 별도 자원 사본을 원본으로 삼지 않는다.
- 전투 HUD는 클릭을 가로채지 않는다. 인벤토리·대장장이·캐릭터 메뉴와 겹치지 않게 숨김/우선순위를 정한다. 사망 안내·대화·상호작용·차징 안내의 위치도 하단 HUD와 겹치지 않게 조정한다.
- 기존 상단 HP/쿨타임 박스는 새 HUD 연결을 확인한 후 제거한다. 기존 ESC 스킬/직업 메뉴를 전부 새 UI로 바꾸는 작업은 포함하지 않는다.

### MP 코어 보류 — 아래 수치는 과거 제안이며 이번에 적용하지 않음

**최종 결정: 이번에는 HUD·아이템 표시만 구현한다. 아래 표와 MP 정책은 이전 제안의 기록이며 승인된 구현 대상이 아니다. 기존 쿨타임의 중앙화도 제외한다.** 현재 코드와 `개발_세부사항.pdf`를 기준으로 기존 직렬화 값·쿨타임·스킬 동작을 유지한다. PDF의 쿨타임·MP 추후 수정 문구를 임의 변경의 근거로 사용하지 않는다.

기존 `ItemSession`과 스킬 상태의 씬 간 유지 구조를 확인했다. HUD는 기존 상태를 조회하고, 회피 등 기존 수명 차이를 이번에 수정하지 않는다. MP 후속 작업도 기존 구조를 먼저 확인하며 새로운 전역 상태나 `DontDestroyOnLoad` 구조를 임의로 추가하지 않는다.

**쿨타임은 현재 구현값을 그대로 유지한다.** 아래 초 단위는 코드 조사 기록이며 실제 씬의 직렬화 값이 있으면 해당 값을 읽는다. MP 수치는 확정된 기획값이 아니다.

MP 비용은 **새 제안**이며 아직 적용하지 않았다. MP바가 실제로 줄고 회복되는 것까지 연결하는 안이다. UI만 먼저 원하면 MP 소모 연결 단계를 분리할 수 있으며, 그 경우 기능이 미연결임을 문서에 명시한다.

- 임시 최대 MP 100, 마지막 소모 후 2초부터 초당 5 회복. 사망 중 자연 회복 중단.
- 씬 이동·메뉴 개폐·스킬 재장착으로 MP나 쿨타임이 공짜로 초기화되지 않게 한다. 직업 변경은 현재 MP 비율을 유지하고, 사망 후 실제 마을 재생성 시 최대 MP로 복구하는 안이다. 부활 자체의 기존 HP/무적 규칙은 유지한다.
- MP 부족·미장착·미습득·사용 불가로 거절된 시도는 MP와 쿨타임을 소비하지 않는다. 조준/차징을 발동 전에 취소하면 비용을 차감하지 않는다. 이미 성공한 시전의 중단은 중복 환급하지 않는다.
- 위 MP 제안은 후속 작업으로 보류한다. 기존 쿨타임을 공통 데이터로 옮기지 않는다. 지속시간·공격력·판정·이펙트도 변경하지 않는다.
- MP 포션 사용, 저장 스키마 변경, 장비의 MP 능력치, 레벨/서버 시스템은 이번 요청에 추가하지 않는다.

### 아이템이 텍스트보다 먼저 보이게 하는 작업

- 기존 확대 슬롯과 스크롤·화면비 대응을 유지한다. 아이콘을 키우려고 슬롯 자체를 다시 작게 만들지 않는다.
- 원본 PNG·아이템 ID·기존 에셋 GUID를 보존한다. 원본의 투명 여백을 조사한 결과를 이용해 **UI 표시용 영역**을 보정하고 작은 패딩만 남긴다. 원본을 잘라 저장하거나 새 원화로 교체하지 않는다.
- 공통 `UpgradeItemIcon` 경로에서 표시를 일관되게 적용한다. 장착 슬롯·가방·제작 화면에서 같은 아이템의 그림 비율이 어긋나지 않게 확인한다.
- 아이콘에는 충분한 고정 영역을 주고 슬롯 이름은 11 수준의 보조 정보로 유지한다. 수량·강화 단계 숫자가 그림을 덮지 않게 모서리로 분리한다. 긴 설명은 기존 상세 영역과 툴팁에 둔다.
- 후광 색·맥동, +1/+2/+3 구분, 아이템 원본 색, 세트 효과와 장착/해제 동작을 보존한다. 여백 보정용 Sprite를 만들면 캐시·정리를 포함해 매 프레임 생성하지 않는다.

### 적용할 스킬과 구현 경로

- **Unity UI / UI Toolkit**: 기존 인벤토리와 같은 런타임 UI 체계로 HP/MP 막대·쿨타임 칸·공통 아이콘 가독성을 구현한다. 공유 PanelSettings 에셋을 직접 바꿔 다른 창의 배율을 흔들지 않는다.
- **Unity IMGUI**: 기존 `PrototypeHud.OnGUI`의 중복 상태 표시 제거와 안내 위치 조정에만 사용한다. 기존 ESC 메뉴 전체를 교체하지 않는다.
- **Unity CLI**: 실제 Unity 컴파일·Play Mode·렌더링 검증에 사용한다. 테스트 저장과 검증 코드는 복사본/로컬 검증 경로에 격리한다. 기존 실행 중인 Editor를 종료하거나 연결 패키지를 무단 설치하지 않는다.
- 이미지 생성·새 패키지·전체 게임 폴리시는 필요한 작업으로 확인되지 않았으므로 이 계획에는 포함하지 않는다.
- 라우팅: 현재 세션에서 직접 조사·계획 작성. 위임 없음. 향후 별도 위임이 필요하면 승인 범위와 기존 미커밋 변경을 전달한다.

예상 코드 범위: `PrototypeHud`, 필요한 읽기 전용 상태 조회 API, 새 전투 HUD(UXML/USS/바인딩), MP 후속 읽기 연동 지점, 공통 아이콘 표시 보정 및 필요한 인벤토리/제작 스타일. MP 코어·밸런스 데이터는 제외한다. 기존 public 메서드·클래스 이름을 불필요하게 바꾸지 않는다. 원본 씬·기존 이펙트·다른 사람의 메타 변경은 수정 대상이 아니다. 실제 파일 목록이 범위를 벗어나면 먼저 이 문서에 이유를 적고 승인 범위를 확인한다.
