# 로그인 흐름 수정 · 2026-11-15

## 완료한 수정

- 온라인 게임 접속 화면의 팀 참가 코드를 사용자가 제공한 값으로 자동 입력한다. 직접 변경도 가능하다.
- 데모·신규 계정의 임시 캐릭터 키를 별도 필드에 보관한다. 플레이어 코드 복구 입력란에 자동으로 넣지 않는다.
- 데모·신규 계정은 닉네임 입력 → 해당 버튼 → 기존 3직업 사진에서 선택 → 접속 순서다. 빈 닉네임은 안내하고 진행하지 않는다.
- 기존 계정은 플레이어 코드를 직접 입력해야 로그인한다. 코드가 비어 있으면 이 PC에 저장된 코드로 대신 로그인하지 않는다. 서버로 입력 닉네임을 보내는 기존 경로는 유지한다.
- 새 계정과 데모의 자동 재접속은 같은 내부 키를 사용한다. 명령행에서 전달한 캐릭터 키도 새 계정/데모 내부 키로 분리해 유지한다.
- 일반 계정 로그아웃에 데모 삭제 문구가 나오지 않도록 구분한다.

## 파일

- 게임 코드: `Assets/_Project/Scripts/Networking/NetworkSandbox.cs` 한 파일.
- 작업 기록: 이 문서.
- 수정 직전 백업: `Library/Validation/LoginFlow-20261115/NetworkSandbox.cs.before`.

## 확인 및 남은 사항

- 변경 부분과 diff 공백 오류만 확인한다. 사용자의 빠른 작업 지시에 따라 Unity 실행·빌드·실서버 접속 테스트는 하지 않는다.
- 실제 Railway 서버의 참가 코드·프로토콜 일치 및 접속 성공은 검증하지 않았다. 코드 수정만으로 원격 서버 상태가 바뀌지는 않는다.
- 닉네임 중복 방지는 사용자 지시에 따라 보류했다. 서버의 승인·저장·계정 삭제 규칙은 수정하지 않았다.
- Unity 컴파일 후 Play를 다시 시작하면 적용된다. 기존 exe 배포본에는 다시 빌드해야 적용된다.
- 커밋·푸시는 하지 않았다.
- 기존 로그인 구현의 제한된 수정이므로 직접 처리했다. 작업자 위임은 하지 않았다.

## 추가 승인 반영 — 일반 로그인 코드 입력 필수

- 새 일반 계정은 기존대로 새 무작위 고유 코드를 자동 발급한다. 코드를 사용자가 직접 정하는 방식으로 바꾸지 않았다.
- 일반 로그인 버튼에서 빈칸·공백 및 잘못된 32자리 GUID 형식은 안내만 표시하고 연결을 시작하지 않는다.
- `restore` 모드는 입력한 코드만 반환한다. 로컬 저장 코드 사용이나 새 코드 자동 생성으로 대체하지 않는다.
- 입력 코드에 해당하는 계정의 존재·동시 접속 여부는 기존 서버 검증을 그대로 사용한다. 닉네임으로 계정을 구분하지 않는다.
- 데모는 입력란의 플레이어 코드와 무관하게 별도 임시 키로 시작한다. 닉네임·직업 선택 및 기존 데모 삭제 동작을 유지한다.
- 이미 접속한 세션의 일시적인 연결 끊김에 대한 자동 재접속은 기존 연결 키를 유지한다. 로그인 화면에서 입력 없이 계정에 들어가는 동작과 구분한다.
- 로그인 화면 문구에 기존 계정 코드 입력 필수, 새 계정 자동 발급·ESC 메뉴 복사, 데모 코드 불필요를 명시했다.
- 이번 추가 변경은 `NetworkSandbox.cs`와 이 기록만 수정했다. 백업: `Library/Validation/LoginExplicitCode-20261115/NetworkSandbox.cs.before`.
- 코드와 diff 공백 검사만 수행한다. Unity 실행·전체 컴파일·실서버 로그인·잘못된 코드 접속 거절을 실제로 시험하지 않았다. 원격 서버 코드는 변경하지 않았다.
