# 2026-11-06 ESC 메뉴 분리

## 승인 범위

- ESC로 여는 첫 화면에는 장비·인벤토리 / 스킬 / 직업 선택 버튼 세 개만 둔다.
- 버튼을 누르면 각각의 기존 UI를 표시한다. 스킬과 직업 선택은 서로 다른 화면으로 분리한다.
- ESC로 메뉴를 닫는 기존 입력 동작을 유지한다.
- 인벤토리 내부 UI, 장비 처리, 스킬 장착 제한, 직업 변경 조건, 전투/HUD 수치는 수정하지 않는다.

## 변경 파일

- 게임 코드: `Assets/_Project/Scripts/World/PrototypeHud.cs` 한 파일.
- 기존 스킬/직업 탭을 제거하고 메인 메뉴와 각 화면의 선택 상태만 분리했다.
- 장비·인벤토리는 기존 `InventoryWindow.Open()`으로 연다.
- 스킬은 기존 `DrawSkills()`, 직업 선택은 기존 `DrawClasses()`를 그대로 사용한다.
- 메뉴를 닫고 다시 열면 첫 메뉴로 돌아온다. 각 화면의 기존 닫기 버튼도 유지한다.
- 다른 화면의 기능, 저장 로직, 네트워크/파티 시스템, 인벤토리 에셋은 변경하지 않는다.

## 검증 현황

- 원본 프로젝트와 분리한 최신 코드 복사본에서 Unity 컴파일 및 Play 모드 실행 검증 20개 통과: `MENU_NAVIGATION_OK checks=20`.
- 스킬/직업 선택 버튼에 연결된 콜백 실행, 창별 상태 분리, 메뉴 재진입 시 초기화, 기존 인벤토리 열기/닫기, 입력 차단/복구, HP/MP·직업·아이템 수·스킬 슬롯 보존을 확인했다.
- 기존 `DrawSkills()`부터 `DrawClasses()` 및 나머지 코드까지 원본과 비교해 변경되지 않았음을 확인했다. ESC 입력을 처리하는 `ArcherController`와 인벤토리 코드는 수정하지 않았다.
- 배치 실행에서는 IMGUI의 화면 Repaint 이벤트가 발생하지 않아 실제 마우스 클릭 및 화면 캡처 검증은 완료하지 못했다. 키보드 ESC 입력 자체도 직접 입력해 확인하지 않았다. 이 검증을 완료했다고 간주하지 않는다.
- 결과: `Library/Validation/MenuSplit-20261106/result.txt`.
- 검증용 코드는 `Library/Validation/MenuSplit-20261106/`에만 두며 배포 게임 코드에는 포함하지 않는다.
- 기존 PNG meta 23개는 변경 전 해시와 모두 일치함을 확인했다.
- 단순한 기존 메뉴 연결 변경이므로 위임하지 않고 직접 수정·검증한다.
